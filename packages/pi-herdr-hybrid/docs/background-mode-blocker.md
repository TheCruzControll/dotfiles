# Background/Pane implementation boundaries

Owner approval permits explicit fail-closed errors for unsupported background settings and cross-backend conversion. There is no automatic Pane fallback.

Background uses the published `pi-subagents@0.84.0` default extension through `src/execution.ts`; no upstream runner internals are copied. This pin includes the GHSA-6v8j-6w28-2w8r workflow VM sandbox escape fix. Repository: https://github.com/nicobailon/pi-subagents.

The facade captures every upstream `subagent` registration, including declaration repins. Events, lifecycle handlers, notifier, tool selection and other APIs pass through to the real host. It deliberately omits `subagents_enable`, selecting upstream's documented eager behavior (without a loader the selection hooks do not unload subagent). Hybrid alone registers the public `subagent`. `subagent_native` exposes the captured native management schema, restricted at execution to status/list/interrupt/stop/resume/steer/debug.run/guide. No native launch bypass is exposed.

## Supported translation and explicit limits

Runtime profiles use exported `registerAgent` for tools, excluded tools, role prompt/mode, model/thinking, skill selection/inheritance and nesting restrictions. Interactive/retained-pane requests, Hybrid preflight, non-Pi profiles, disabled model invocation, inherited Hybrid deny environment, and child-specific agent config directories are refused before upstream execution with instructions to select Pane explicitly. Explicit standalone profiles are also refused: upstream fresh retains parent lineage. Ordinary unspecified context uses fresh; `lineage-only` maps to fresh, and fork maps to fork. Inspection of published `child-launch.js` and `child-session.js` confirms fresh creates new history and writes the parent session header; enum spelling alone is not a behavioral blocker.

Background receipts retain the exact upstream run id in `details.id` and append `hybrid-background` session entries. Pass that id as `subagent_resume.sessionPath`, or use native resume with its exact id. Pane paths remain pane resumes regardless of current preference; converting either backend explicitly fails. Native resume validates upstream retention/ownership and may reject a run; Hybrid never substitutes a fresh launch. Runtime agent registrations are disposed after execution (including failures); their definitions are recorded on the branch and temporarily re-registered for eligible native resume. Resume eligibility is still decided by upstream recovery. Background resume under the updated workflow controller owns a new reservation for the exact terminal native id and preserves its recorded model and cwd.

The backend admission bridge reserves a UUID before upstream execution, with the resolved cwd and explicit provider/model selector (including thinking suffix). The controller retains selected-task, model authorization, writer isolation, capacity and owner checks; an older controller refuses the protocol rather than being bypassed. Exact non-parent model ids are validated with the public host model registry. New launches pass that same explicit model at the top level to upstream, which retains its own policy enforcement. Resume authorizes the saved model with the controller but sends no model override: upstream reuses its persisted child model. Public `subagent:async-started` binds the reservation to the native id/sessionRoot; pinned 0.84.0 identifies single launches by their unique registered agent name (the bridge also accepts toolCallId when supplied). No invented session filename is used. Completion records the real session path when published. Unknown dispatch failures retain active ownership; only known pre-execution validation failures retire a reservation. Public preflight's inability to discover runtime registrations is covered by a regression test but is not needed for this narrow model-selector admission contract.

Workflows freeze executionMode on all steps at start, observe `subagent:async-complete` for progression and retain their own workflow-level summaries. Upstream alone owns background child result delivery. Pane watchers and notification behavior are unchanged. Interruption dispatches recorded background ids to upstream; pane ids retain Herdr interruption.

## Updating upstream

Use an exact, reviewed version: `npm install --save-exact pi-subagents@<version> --ignore-scripts --legacy-peer-deps`. Preserve/restore existing host peer symlinks; do not install extra Pi copies. Review package-lock.json and upstream security/changelog notes, then run `npm test`, facade/translation/preference tests, and live Background/Pane launch/resume/interrupt/workflow checks before promoting. Never change to a floating range or import a developer checkout. No runtime package copying or global configuration writes are needed.

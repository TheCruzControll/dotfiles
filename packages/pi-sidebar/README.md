# Local Pi right sidebar (experimental, Pi 1.4–1.5)

This isolated refinement is **not installed**. It changes no canonical dotfiles, Pi core, settings, or Herdr integration. To try the isolated package in a fresh session:

```sh
pi --extension /absolute/path/to/this/directory/index.ts
```

The sidebar starts **hidden** on session start and reload. **Ctrl+Shift+B** or **`/sidebar`** toggles visibility. The shortcut requires a terminal that distinguishes Ctrl+Shift+B from Ctrl+B. No goal/task state or session entries are written.

## Behavior

- Supports Pi 1.4's default **fullscreen** viewport and **regular** layout with guards against unknown structures.
- At widths 80–99, reserves a compact 26-column sidebar and two-column gutter (80 columns gives 52 chat columns). At >=100, preserves the 34–46-column sidebar (23% where readable). When toggled hidden, chat gets full width while retaining only the compact context/model footer; sidebar widgets and extra footer details stay hidden. Automatic narrow-window fallback below 80 columns (while enabled) still restores native widgets and details. Live context remains visible even with no widgets. A split pane around 80 columns can now show the sidebar; if it says `Sidebar hidden`, use `/sidebar` or Ctrl+Shift+B to enable it.
- Clean, padded sections replace nested widget framing. The title uses the session name or project basename; recorded session spend appears under Cost only when available. Cwd is anchored at the bottom. Text uses theme foregrounds; the surface is fixed neutral charcoal, independent of `userMessageBg` (including blue themes). Context is absent from the sidebar. Live compact context, e.g. `24.8k · 12%`, leads the single muted chat footer line before model/thinking, so long model identifiers cannot displace it at compact 52-column chat widths. Zero is shown as `0 · 0%`; unavailable estimates are shown as `Tokens ? · Usage ?`, never fabricated. Reads use the public `ctx.getContextUsage()` callback on each active footer render. Bold sidebar headings consistently identify Cost, Model, Conductor, Activity and Workspace. Conductor has its own section between Model and Activity; other extension statuses stay under Activity. When its live status is present and enabled, recorded current-branch/current-project task snapshots supply labeled Playbook and Goal (the recorded scope) fields. Constraints and Waiting on (recorded pending review/approval and outstanding checks) appear only when present. Stage, verification results, and playbook rationale are not displayed. Each field wraps to at most three lines, with an ellipsis and `/conductor status` hint for longer content. Terminal-height overflow also points to `/conductor status`; lower sections can be crowded out. Without matching task records, the original live status remains the fallback; off mode shows only its status, and an absent status adds no heading. These are recorded updates, not inferred agent thoughts or progress. Native model/routing data and extension statuses are grouped semantically rather than classified from rendered strings. Observer/below-editor text belongs to Activity; existing Goal/Todos headings are retained without adding a duplicate Tasks heading. Unlabeled above-editor content gets a Tasks heading. Empty sections add no heading.
- Moves the **entire above-editor widget area**, including pi-goal-x goal and rpiv-todo task widgets. Other above-editor widgets also move. There is no public widget-key registry and todo's component is anonymous, so this avoids brittle identity detection. Below-editor widgets also move, preserving their text (including idle labels such as `Observer off /observer on` and shortcut hints), with wrapping only—no idle filtering or framing normalization. Pi's core working/cancel indicator remains native. With the sidebar active, the footer becomes one muted context + model/thinking line; provider/model routing details and live extension workflow/background statuses move to the sidebar. Native cache read/write/hit counters are not copied.
- Uses the original live widget components: no copied goal/task state, polling, commands, or mutations. Conductor details are read-only projections of existing session branch records; they introduce no timers, writes, or execution changes. Toggling off hides their display without changing their state; toggling back on shows their current content in the sidebar. Only automatic narrow-window fallback while enabled restores them under chat.
- Panel fills the terminal-visible height in both modes; oversized content shows a details-command hint while reserving Workspace immediately above the bottom path (path only at one row). Truncation does not leave a section heading without its content. Earlier widgets can crowd later ones out; `/goal` and `/todos` remain available.
- Sidebar is display-only. Fullscreen consumes sidebar pointer events without focusing or scrolling chat. Native chat hit testing, ScrollView scrolling and keyboard input remain in place. Regular-mode terminal scrollback can retain old sidebar frames.

The compact footer also shows `subagents N active` beside context usage when upstream pi-subagents is available, including when the sidebar is hidden. It reads the upstream fleet snapshot through read-only event-bus RPC on startup/ready/job changes, with no polling or copied job registry. Zero remains visible after completion; absent/invalid replies leave the existing footer unchanged. This counts upstream native children, not independent Herdr Pane children.

## Integration

No public persistent sidebar API exists. An overlay was rejected because it obscures chat. `setWidget` supplies a real host TUI and an invisible probe. Private layout shape guards require seven root containers and the probe in the above-editor container.

Regular mode uses a local render adapter, briefly suppressing both above- and below-editor renders and compacting the footer in `try/finally`, with ANSI-aware column composition. Original render descriptors are restored even on errors. Native footer ownership is guarded by its session and footer-data provider; unknown/custom footers fail closed. Public `setFooter` was rejected: it disposes an existing custom footer, and resetting it only restores Pi's built-in footer, not that custom instance. Scoped interception retains original instances and uses their live data without parsing painted footer text.

Fullscreen additionally validates the existing `createChatViewport` root: VStack with transcript ScrollView and six-entry dock containing both widget containers and the footer. A native HStack wrapper becomes the layout root, retaining the **original root and all focusable descendants**. Dynamic entries allocate the original chat subtree and a display-only side component. Pi's native `renderLayoutFrame` thus calculates actual narrower ScrollView, cursor, clipping and mouse boxes on each viewport resize, rather than just narrowing painted text. Both widget-container renders return zero rows while this wrapper owns them and the sidebar is visible or manually disabled, covering both intrinsic measurement and painting. The footer keeps its compact line in both toggle states. Only automatic narrow-window fallback while enabled appends the original native footer. Side rendering calls the saved live renderer directly. Cleanup restores both widget render descriptors, the footer render descriptor, and the original root if still owned. A replaced container or later render adapter disables sidebar suppression without overwriting the newer owner. The adapter uses Pi 1.4's internal layout-node symbol because it is not exported from the public barrel.

Shutdown/reload cleanup is idempotent. It never overwrites a later render/root adapter. Unknown layouts fail closed with original widgets unchanged and a warning. Switching Pi rendering modes creates another renderer; widgets remain native there until `/reload` reattaches the sidebar. Future internals or competing layout extensions can conflict despite guards.

## Tests

```sh
node --test tests/*.test.mjs
```

No dependencies installed. Tests intentionally use the supplied machine-local Pi 1.4.0 and 1.5.0 installations, jiti and Node test runner. They cover real `TuiMainScreen`, real `TuiAltScreen` + exported `createChatViewport` + native viewport renderer; wide/narrow/empty resize, terminal heights, live updates, keyboard forwarding, editor mouse coordinates, sidebar wheel isolation versus transcript wheel scrolling, root membership/focus, ANSI/unicode widths, cursor marker retention, toggle, unsupported layouts, height capping, exception restoration and shutdown/reload command wiring.

The refinement suite passes 38 checks (19 each with existing installed 1.4.0 and 1.5.0 runtimes). Added regression coverage checks neutral surfaces under a blue theme, compact context, live model/thinking/status updates, working/cancel retention, cache-counter omission while active, minimal under-chat rendering on manual toggle and native footer/widget fallback on narrow resize while enabled, and custom/replaced footer guards. Split-layout regressions exercise 79/80/90/99/100-column boundaries in the real fullscreen renderer, including cursor, focus, mouse width, resize, live below-widget content, exception recovery and later-adapter ownership. Regular-mode tests also cover below-widget fallback and descriptor restoration. Heading regressions were added failing-first, then verify semantic groups, ordering, bold styling, no empty/duplicate headings and bounded output at heights 1–12. Earlier heading component-render evidence at widths 26/34 is retained in `.pi/sidebar-headings-render.txt` and `.pi/sidebar-headings-render.ansi` (it predates context relocation). Context relocation was added failing-first (`.pi/sidebar-context-red.txt`); final evidence is `.pi/sidebar-context-tests.txt`. It checks footer placement and live public callback updates in regular/fullscreen layouts, zero/unavailable estimates, context retention with long model names at 52 chat columns, no sidebar context, and Cost labeling. Component tests are not real-terminal appearance verification. Real terminal smoke testing was attempted with a dedicated tmux server, but this isolation environment rejected pane creation: `create window failed: fork failed: Operation not permitted`. No interactive-terminal or graphical validation of this refinement is claimed.

Toggle retention regressions cover live compact usage updates while hidden and after re-enabling the sidebar in both regular and real fullscreen viewport rendering, with no extra native details or relocated widgets while manually hidden.

Not checked: real-goal interactions, graphical appearance in the owner's terminal, IME/inline graphics, cross-pane text selection, interactions with other rendering extensions, or static TypeScript compilation. Private integration remains experimental.
